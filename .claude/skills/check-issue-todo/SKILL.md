# 이슈 To-Do 체크

## 1. 이슈 번호 찾기

- `git branch --show-current`에서 `feature/#<번호>-...`의 번호를 쓴다.
- 브랜치에 번호가 없으면 아무것도 하지 않고 끝낸다 (묻지 않는다).

## 2. 이슈와 변경 내용 읽기

```bash
gh issue view <번호> --json body -q .body
git log --oneline origin/develop..HEAD
git diff --stat origin/develop...HEAD
```

필요하면 해당 파일을 직접 열어 To-Do 항목이 정말 구현됐는지 확인한다.

## 3. 판단 기준

- **체크하는 것**: 커밋된 코드로 완료가 확인되는 항목만. 커밋되지 않은 변경은 근거로 쓰지 않는다.
- **체크하지 않는 것**
  - 일부만 된 항목 (예: 4곳 중 3곳 배치)
  - 실행 결과로만 알 수 있는데 이번 세션에서 확인하지 않은 항목 (lint / 타입체크 / 빌드 통과 등)
  - 사용자가 직접 해야 하는 항목 (DB 마이그레이션 실행, 배포 등) — 사용자가 했다고 말한 경우만 체크
- 하위 항목이 모두 체크되면 상위 항목도 체크한다.
- 이미 체크된 항목은 해제하지 않는다.
- 구현 방식이 To-Do 문구와 달라도 목적을 달성했으면 체크하고, 차이는 결과 보고에 적는다.

## 4. 반영

- 본문에서 `- [ ]` → `- [x]`만 바꾼다. 그 외 문구·순서·공백은 건드리지 않는다.
- 본문을 임시 파일로 저장한 뒤 `gh issue edit <번호> --body-file <파일>`로 반영한다.
- 바뀐 항목이 없으면 수정하지 않는다.

## 5. 보고

짧게 정리한다.

```
#31 To-Do 체크: 12개 중 10개 완료
- 새로 체크: 버튼 배치(헤더), mock 데이터 추가
- 남은 항목: lint / 타입체크 / 빌드 통과 (빌드 미확인)
```
