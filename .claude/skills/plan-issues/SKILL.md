# 이슈 작성

## 절차

1. 레포의 AGENTS.md / CLAUDE.md와 관련 코드를 읽고 맥락을 파악한다.
2. 기능을 **PR 하나로 끝낼 수 있는 크기**로 쪼갠다.
   - 기준: 한 브랜치에서 하루 안에 리뷰 가능한 양
   - 의존 순서대로 나열 (예: DB 스키마 → 서비스 → UI)
3. **생성 전에** 이슈 목록을 먼저 보여주고 확인받는다.
   ```
   1. 스킬 메타데이터 스키마 추가 — 테이블·마이그레이션
   2. 스킬 메타데이터 관리 페이지 — 폼, 액션
   ```
4. 확인되면 `gh issue create`로 하나씩 생성하고, 생성된 이슈 번호와 링크를 정리해서 보여준다.
5. 3개 이상으로 쪼개진 큰 기능이면 상위 이슈를 하나 만들고 본문에 하위 이슈를 `- [ ] #번호`로 링크한다.

## 이슈 본문

레포에 `.github/ISSUE_TEMPLATE/`이 있으면 그 형식을 그대로 쓴다. 없으면 아래 형식.

```markdown
## 📌 작업 내용

무엇을, 왜 하는지 2~3줄.

## ✅ To-Do

- [ ] 구체적인 작업 단위
- [ ] ...
- [ ] lint / 타입체크 통과

## 📝 참고사항

- 참고할 기존 파일: `path/to/file.tsx`
- 완료 조건: 무엇이 되면 끝인지 한 줄
```

To-Do는 나중에 구현할 때 "어디까지 하면 끝인지"의 기준이 되므로 구체적으로 쓴다. 참고할 기존 파일을 꼭 적는다.

## 제목

- 한국어, 명사형으로 끝낸다. 예: `프로젝트 기술 스택 삭제 기능`, `Section 컴포넌트 구현`
- 제목에는 이모지를 넣지 않는다.

## 라벨

레포에 있는 라벨만 쓴다 (`gh label list`로 확인). 없으면 붙이지 않는다.
